# Мой онлайн v0.4.0 — экспериментальная проверка фильма Rezka

Следующий этап после успешного `PAGE_AVAILABLE` на Render. Добавлены чтение озвучек для конкретной карточки «Гладиатор» (1986), запрос ссылок выбранной озвучки, выбор качества и запуск Lampa.Player. Это экспериментальный адаптер: настоящий ответ авторизованного плеера rezka.si в этой среде не получен, воспроизведение фильма на TCL пока не проверено. Общий поиск и сериалы ещё не реализованы.

Карточка: https://rezka.si/films/action/93568-gladiator-1986.html . Пункт проверки всегда открывает именно её, независимо от текущего фильма в Lampa. В меню это явно указано.

## Обновление

1. Загрузите все файлы из ZIP в корень существующего GitHub-репозитория с заменой. Обязательно добавьте новые `player-data.js`, `player-data.test.js`. Файлы из предыдущих версий вне архива не нужны; архив не содержит личных данных.
2. Render → Environment: оставьте работающие `REZKA_LOGIN`, `REZKA_PASSWORD`, `PUBLIC_BASE_URL`. Не меняйте их, если уже получили PAGE_AVAILABLE.
3. Добавьте **MY_ONLINE_TOKEN** — придумайте отдельный случайный код из 24–32 латинских букв и цифр. Допускаются также дефис и подчёркивание, всего 16–128 символов. Это код доступа к вашему серверу, а не пароль от Rezka. Не помещайте его в GitHub и не присылайте в чат.
4. Сохраните настройки и разверните последний commit. Настройки сервиса прежние: Build `npm install`, Start `npm start`, Health Check `/health`, Node.js 22+, файлы в корне репозитория. `render.yaml` не меняет автоматически настройки существующего сервиса.
5. Убедитесь, что https://lampa-my-online.onrender.com/health показывает **0.4.0**. После запуска /api/rezka/status сначала может показывать CHECKING, затем PAGE_AVAILABLE. Дополнительное поле `playerRecognized: true` означает, что найден поддержанный блок плеера. Это не проверка видео.
6. В Lampa замените старую запись плагина на `https://lampa-my-online.onrender.com/plugin.js?v=0.4.0`. Полностью закройте Lampa, откройте снова и заново откройте карточку фильма. Старые записи плагина удалите, чтобы не было двух кнопок.
7. Мой онлайн → **Ввести код доступа к серверу** → введите значение MY_ONLINE_TOKEN → завершите ввод клавиатурой/кнопкой Назад. Пустой ввод не меняет сохранённый код. Код хранится локально на устройстве Lampa; не показывайте экран ввода посторонним. Это НЕ форма входа Rezka.
8. Мой онлайн → **Rezka: Гладиатор (1986) — проверка фильма** → выберите озвучку → качество MP4 или HLS. Только после успешного ответа сайта ссылка передаётся плееру. Никакой выдуманной ссылки и подмены фильма тестовым роликом нет.

Напишите результат: «появились озвучки», «появилось качество», «фильм играет» либо точный код ошибки. Не присылайте код доступа, пароль, cookie или видеоссылку. Старый ролик с цветами не менялся.

## Ошибки

| Код | Что означает |
|---|---|
| ACCESS_CODE_NOT_CONFIGURED | На Render нет корректного MY_ONLINE_TOKEN |
| ACCESS_DENIED | Введите в Lampa тот же код, что указан в MY_ONLINE_TOKEN |
| CHECKING | Проверка при запуске сервера ещё не закончилась |
| AUTH_REQUIRED / LOGIN_REJECTED | Проверьте прежние настройки входа на Render; не перезапускайте много раз подряд |
| PLAYER_NOT_RECOGNIZED | Карточка доступна, но блок плеера не совпал с поддерживаемым форматом |
| SESSION_EXPIRED | Сессия закончилась; нужна новая проверка при перезапуске сервера |
| STREAM_INVALID_JSON | Сайт вернул неожиданный ответ на запрос видео |
| STREAM_REJECTED | Сайт отклонил запрос видео; пароль или подписку по этому коду определить нельзя |
| STREAM_FORMAT_UNKNOWN | Неподдерживаемая упаковка ссылки; код останавливается, не пытается угадать URL |
| NO_PLAYABLE_STREAMS | Нет подходящих доступных HTTPS MP4/HLS; ссылки с премиум-метками пропускаются |
| WAIT_AND_RETRY | Предыдущий запрос выполняется или прошло меньше двух секунд; повторите немного позднее |
| BLOCKED / RATE_LIMITED | Сайт ограничил запрос сервера (403 / 429) |
| PROVIDER_ERROR | Другая ошибка получения данных; личный текст ответа сайта наружу не выдаётся |

Если качество выбрано, а фильм не запускается, это ещё не означает ошибку авторизации. Ссылки CDN могут иметь срок действия или зависеть от сети, заголовков и IP сервера. В этой версии видео идёт напрямую CDN→TV; проксирования через Render нет. Ошибку декодирования/воспроизведения показывает сама Lampa. Смена настройки встроенного/внешнего проигрывателя зависит от вашей Lampa.

## Что реализовано

Вход — по проверенной форме rezka.si: POST `/ajax/login/`. Сессионные cookie остаются в памяти серверного процесса для запросов плеера. Нет записи cookie на диск, передачи пароля в плагин или вывода секретов в логи. Сторонние редиректы отклоняются. Одно выполнение входа при запуске, без автоматической повторной авторизации при ошибке. Для восстановления сессии нужен перезапуск. Учитывайте, что Render может перезапускать процесс самостоятельно.

Метаданные плеера читаются без выполнения JavaScript страницы. Поддерживается `initCDNMoviesEvents` с ID 93568, список `.b-translator__item`, числовые ID озвучек и их flags. Запрос фильма: POST `/ajax/get_cdn_series/`, action=get_movie, id, translator_id, is_camrip/is_ads/is_director. Контракт сверён с открытым клиентом go-hdrezka, а не с живым авторизованным запросом rezka.si. Поэтому совместимость конкретного зеркала ещё предстоит проверить.

Поддерживаются явные ссылки, известная упаковка #h/base64 и известные маркеры вставок. Незнакомая упаковка не угадывается. Берутся только реально полученные HTTPS MP4/HLS; URL не конструируются заменой суффиксов. Качества с премиум-меткой не выдаются за доступный фильм. Данные не исполняются через eval, HTML сайта не возвращается клиенту.

## API и доступ

Публично: `/health`, `/plugin.js`, `/api/demo`, `/api/rezka/status`. Статус не содержит озвучек, видеоссылок, email или cookie. `/api/search` пока остаётся заглушкой без каталога Rezka.

Защищено: GET `/api/rezka/movie`, GET `/api/rezka/stream?translator=ID` — обязательный заголовок `Authorization: Bearer MY_ONLINE_TOKEN`. Передача кода в URL не поддерживается. Без кода нет запросов к провайдеру. Ключ не встраивается в JS сервера и не отдаётся в публичном статусе. CORS допускает заголовок Authorization, но не предоставляет доступ без кода.

Один запрос ссылок за раз, пауза минимум две секунды, кеш ссылок на 60 секунд в памяти. Запросы озвучек разрешены только для ID из разобранной карточки. Сервис не принимает произвольный URL сайта и не является открытым видеопрокси.

Поле streamReady становится true после получения подходящих ссылок, не после доказанного воспроизведения на телевизоре. /health rezkaConnected отражает это же состояние. Подтверждение полноценной работы — реальный запуск фильма на вашем TCL.

## Проверки

Node.js 22+: `npm test` или `node --test`; `npm start`. Нет сторонних зависимостей. Автотесты: HTTP API, запрет доступа без/с неправильным кодом, отсутствие кода в JS и публичных ответах, передача кода в заголовке из Lampa, меню озвучка→качество→Player, вход без повторов, сохранение cookie для запроса плеера, кеш, неизвестные озвучки, распаковка, недопустимые ссылки, премиум-метки, редиректы и ошибки.

Тестовые ответы авторизованной Rezka имитированы. Разработчик не получал пароль пользователя и не выполнял вход в его аккаунт. Успешные автотесты не означают проверку реального видеопотока.

Сверка протокола: https://github.com/n0madic/go-hdrezka/blob/master/video.go и https://github.com/n0madic/go-hdrezka/blob/master/stream.go . Собственная реализация, не подключает и не запускает стороннюю библиотеку. Тестовый ролик MDN сохранён с предыдущих версий.
