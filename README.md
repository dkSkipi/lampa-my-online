# Мой онлайн — Lampa Online Starter v0.2.0

Диагностическая версия для Lampa / Android TV. Работает через GitHub и существующий Web Service Render. Без сторонних зависимостей Node.js. Не содержит доступа к Rezka, поиска реальных фильмов, авторизации или извлечения потоков. Не вводите пароли в этот проект.

## Что выяснилось

3 ноября 2026 проверены опубликованные `/plugin.js`, `/health` и `/api/search?q=Test`: ответы HTTP 200, сервер v0.1.0, тестовый каталог. Фото телевизора показывает штатное сообщение об отсутствии выбранного фильма, а не сетевой сбой. Старый каталог находил только Big Buck Bunny по названию. Произвольный фильм всегда давал пустой список.

Дополнительно в старом компоненте найдены обращения к глобальному `Navigator` вместо `Lampa.Navigator`, таймаут 20 секунд и отсутствие кнопки повтора на пустом экране. Это дефекты кода, но фото не доказывает, что они вызвали наблюдаемую ситуацию. Старый URL видео при проверке HEAD вернул 403. Новый MP4 из примеров MDN вернул 206 на запрос диапазона 0–31 байт.

Исходный ZIP `/mnt/data/lampa-online-starter-v0.1.zip` недоступен. Для исследования получены действующий `/plugin.js` и `server.js` из публичного GitHub dkSkipi/lampa-my-online (main). v0.2 заменяет сервер и интерфейс; старые сторонние пакеты больше не нужны.

## Обновление существующего GitHub и Render

1. Распакуйте ZIP. Загрузите **содержимое** архива в корень своего репозитория https://github.com/dkSkipi/lampa-my-online с заменой файлов. `package.json`, `package-lock.json`, `server.js`, `plugin.js`, `project.test.js`, `README.md`, `render.yaml` должны лежать рядом. Не загружайте сам ZIP вместо файлов.
2. Сохраните изменения (Commit changes). Старый `package-lock.json` обязательно замените новым из архива.
3. В существующем сервисе Render проверьте: Root Directory пустой (если файлы в корне); Build Command: `npm install`; Start Command: `npm start`; Health Check Path: `/health`. Новый сервис создавать не нужно. `render.yaml` — вариант для развёртывания через Blueprint; существующий сервис он сам не перенастраивает.
4. Environment: `PUBLIC_BASE_URL` = `https://lampa-my-online.onrender.com` (без `/plugin.js`). Если переменная не задана, используется `RENDER_EXTERNAL_URL`, затем адрес загруженного скрипта в браузере. Node.js: 22 или новее. `PORT` предоставляет Render; сервер слушает `0.0.0.0`.
5. Manual Deploy → Deploy latest commit. Дождитесь Live. Откройте https://lampa-my-online.onrender.com/health — должна появиться версия **0.2.0**, `ok: true`, `rezkaConnected: false`. Если версия 0.1.0 — обновление ещё не применилось.
6. В Lampa удалите старую запись этого плагина и добавьте `https://lampa-my-online.onrender.com/plugin.js?v=0.2.0`. Полностью закройте Lampa и откройте снова. Это убирает старый обработчик v0.1 из памяти. При двух кнопках проверьте, нет ли второго адреса старого плагина, и снова перезапустите приложение.
7. Откройте заново карточку любого фильма → **Мой онлайн**. Должно открыться меню с заголовком **v0.2**.

## Проверка на TCL Android TV

1. «Диагностика соединения»: ожидается `OK`, сервер и плагин 0.2.0. После простоя первый запрос может потребовать ожидания; таймаут плагина 90 секунд, повтор — выбор пункта меню ещё раз.
2. «Запустить тестовый ролик» → выбрать MP4. Ожидается короткое видео с цветами из примеров MDN, а не фильм из открытой карточки. Вызывается `Lampa.Player.play`; фактический встроенный/внешний проигрыватель зависит также от настроек вашей Lampa.
3. «Проверить источники фильма»: ожидается честное сообщение, что источники и Rezka не подключены. Пустой результат здесь нормален.
4. Кнопка «Назад» закрывает меню. При сетевой ошибке меню можно открыть повторно.

Если видео не играет, но диагностика OK: соединение Lampa→Render работает, проверяйте доступ телевизора к домену видео и настройки проигрывателя. Успешная передача ссылки в плеер не доказывает декодирование видео. Ошибки самого проигрывателя показывает Lampa; универсального подтверждённого события ошибок для всех версий Lampa этот плагин не перехватывает. Сначала можно открыть главную страницу сервера в браузере и проверить встроенный там тестовый ролик.

## Сообщения ошибок

| Код | Что делать |
|---|---|
| TIMEOUT | Дождитесь запуска Render, откройте `/health`, повторите запрос |
| NETWORK | Проверьте интернет, DNS, HTTPS и доступность сервера с телевизора; возможна блокировка CORS/сети |
| HTTP_… | Проверьте Render и адрес API; запишите код ответа |
| INVALID_JSON | API вернул HTML или другой ответ вместо JSON; проверьте адрес и логи Render |
| API_MISMATCH | Замените все файлы сервера; требуется версия 0.2.0 |
| MENU_ERROR / CLIENT_ERROR / BUTTON_ERROR | Запишите сообщение и версию Lampa |
| EMPTY_DEMO | Проверьте `/api/demo` и соответствие версии сервера |

Для дальнейшей диагностики достаточно фото сообщения, версии Lampa и ответа `/health`. Логины, пароли и cookie не нужны. Сервер не проксирует видео и не принимает секреты.

## Локальный запуск и проверки

Установите Node.js 22+. В папке проекта: `npm install`, затем `npm test`, затем `npm start`. Откройте `http://localhost:10000/`. Адрес localhost доступен только на этом компьютере, для телевизора нужен опубликованный адрес Render.

API: GET `/health`, `/api/demo`, `/api/search?q=Название`, `/plugin.js`. JSON без кеширования, CORS `*` без cookies, OPTIONS и HEAD поддерживаются. Неверный запрос даёт 400, неизвестный путь 404, неподдерживаемый метод 405. Сервер не строит адрес API из недоверенного заголовка Host.

Автотесты проверяют реальный локальный HTTP-сервер, CORS, ошибки, версию, подстановку адреса и работу логики меню в имитации API Lampa (выбор ролика, вызов Player, таймаут, неверный JSON, несовместимая версия, повторная загрузка). Это не заменяет проверку пульта и проигрывания на TCL. Реальная Lampa на телевизоре здесь не запускалась.

Тестовое видео: https://interactive-examples.mdn.mozilla.net/media/cc0-videos/flower.mp4 — пример MDN, CC0; файл не включён в архив. Доступность внешнего URL может измениться. Пример video: https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/video .

## Дальнейшее подключение источников

Следующий этап требует реально проверенного способа доступа к каталогу/потокам провайдера и тестов его ответов. В v0.2 такой адаптер не реализован. Название фильма не преобразуется в выдуманный URL; тестовый ролик никогда не выдаётся за найденный фильм.
