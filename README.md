# Мой онлайн v0.3.0 — проверка входа на Rezka

Это промежуточный этап подключения Rezka: сервер проверяет вход и доступность карточки фильма. Поиск, озвучки, серии и получение видеопотока ещё не реализованы. Рабочий тест плеера v0.2 сохранён без замены ролика.

## Что подтверждено 3 ноября 2026

Проверена ссылка пользователя: https://rezka.si/films/action/93568-gladiator-1986.html . Прямой запрос curl без браузерного User-Agent получил HTTP 403. С `User-Agent: Mozilla/5.0` получен HTTP 200, но содержимое — «Вход на HDrezka», а не карточка фильма. То есть 200 сам по себе не подтверждает доступ к фильму.

В реальной форме подтверждены POST `/ajax/login/`, поля `login_name`, `login_password`, `login_not_save=0` и проверка `success` в JSON. Код использует именно этот контракт. Вход с настоящим аккаунтом разработчиком не проверен: личные данные пользователя не запрашивались. Проверка формы возможна без входа; ссылки на видеопотоки не выдумываются.

## Обновление GitHub / Render

1. Распакуйте архив и загрузите **все файлы из его корня** в корень существующего репозитория `dkSkipi/lampa-my-online` с заменой. Включите новые `rezka.js` и `rezka.test.js`. Замените также package-lock.json.
2. В существующем Render Web Service: Root Directory пустой, если файлы в корне; Build Command `npm install`; Start Command `npm start`; Health Check Path `/health`; Node.js 22 или новее.
3. В Render → Environment добавьте **самостоятельно**:

| Имя | Значение |
|---|---|
| PUBLIC_BASE_URL | https://lampa-my-online.onrender.com |
| REZKA_LOGIN | Ваш email для rezka.si |
| REZKA_PASSWORD | Ваш пароль для rezka.si |

Введите данные только в настройках вашего сервиса Render. Не добавляйте их в файлы GitHub, `.env`, plugin.js, ссылки или сообщения в чате. Эта настройка передаёт данные серверу вашего сервиса Render, который отправляет их исключительно на `https://rezka.si/ajax/login/` для входа. Если не хотите хранить учётные данные в Render, пропустите их: будет проверена только доступность страницы входа.

4. Сохраните настройки и разверните последний commit. Дождитесь Live.
5. Откройте https://lampa-my-online.onrender.com/health — ожидается версия `0.3.0`. Поле `rezkaConnected: false` означает, что воспроизведение фильмов ещё не подключено.
6. Откройте https://lampa-my-online.onrender.com/api/rezka/status . Если статус `CHECKING`, обновите страницу примерно через минуту. Публичный адрес показывает только результат проверки, без логина, пароля, cookie и текста ответа сайта.
7. В Lampa замените старую запись плагина на `https://lampa-my-online.onrender.com/plugin.js?v=0.3.0`, полностью закройте и снова откройте Lampa. Не держите одновременно старые записи плагина.
8. Откройте карточку → «Мой онлайн» → «Проверить вход на Rezka».

## Результаты

| Код | Значение / действие |
|---|---|
| CHECKING | Проверка ещё выполняется; обновите страницу статуса позднее |
| AUTH_REQUIRED | Сайт доступен серверу, но нужна авторизация; проверьте Environment |
| CONFIG_INCOMPLETE | Задана только одна из двух переменных входа |
| LOGIN_REJECTED | Сайт не подтвердил вход; проверьте вход самостоятельно в браузере, не перезапускайте сервис много раз |
| PAGE_AVAILABLE | Узнаваемая карточка фильма доступна; видео ещё не подключено |
| LOGIN_REQUIRED_AFTER_SUCCESS | Сайт принял вход, но не открыл карточку; возможна проблема с сессией |
| PAGE_UNRECOGNIZED | Ответ не совпал с ожидаемыми признаками карточки; нужен анализ её структуры |
| BLOCKED | HTTP 403 именно с сервера Render; вход в домашнем браузере этого не устраняет |
| RATE_LIMITED | HTTP 429; сайт ограничил запросы, не повторяйте вход сразу |
| REDIRECT_REJECTED | Перенаправление за пределы rezka.si либо после отправки формы; секреты дальше не отправлены |
| INVALID_RESPONSE | После формы входа пришёл неожиданный ответ вместо ожидаемого JSON |
| NETWORK / UPSTREAM_HTTP | Сеть сервера или ошибка сайта |

Пришлите только `code` и `message` результата `/api/rezka/status`. Этого достаточно для выбора следующего шага. Не присылайте страницу Environment и личные данные.

## Как устроена проверка

Одна проверка на запуск серверного процесса: карточка → при необходимости форма входа → повторная карточка. Публичный запрос статуса никогда не инициирует вход. Нет автоматических повторов при неверном пароле. Для новой проверки после исправления настроек нужен перезапуск сервиса. Масштабирование/перезапуск Render создаёт новую проверку, поэтому не используйте несколько экземпляров для этой стадии.

Cookie используются только внутри проверки и очищаются после неё; в файлы, ответы API и логи они не попадают. Перенаправление с секретами запрещено. HTML сайта не возвращается клиенту. Учётные данные не вставляются в плагин. Поскольку сейчас наружу доступен только диагностический статус, аккаунт не предоставляется пользователям публичного API. Перед будущим добавлением поиска/видео потребуется ограничить доступ к личным API.

Проверка `PAGE_AVAILABLE` основана на признаках карточки, а не на получении видеопотока: нужна `b-content__main`, ID 93568 и отсутствие формы входа. Этот формат после авторизации на rezka.si пока не подтверждён живым ответом; неизвестный формат даёт `PAGE_UNRECOGNIZED`, а не ложное обещание воспроизведения.

## Проверки проекта

Node.js 22+: `npm test` (эквивалент `node --test`), `npm start`. Вручную без запуска сервера: `node rezka.js` — выводится только безопасный диагностический JSON; при наличии переменных окружения выполнит одну попытку входа.

Автотесты проверяют локальный HTTP API, меню Lampa в имитации, обработку ошибок, контракт формы, cookie в пределах сайта, отсутствие секретов в статусе, отсутствие повторных входов и остановку на сторонних перенаправлениях. Ответы авторизованной Rezka в тестах имитируются; это проверка логики, не доказательство реального доступа. Живые логин/каталог/видеопоток пока не проверены. Работа меню и плеера v0.3 на TCL также требует проверки.

Старые пункты «Диагностика соединения», «Запустить тестовый ролик» работают как в v0.2. «Проверить источники фильма» по-прежнему сообщает, что источники фильма не подключены. Наличие аккаунта и успешный вход сами по себе не означают наличие поддерживаемого способа получения видео для Lampa.
